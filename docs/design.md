# 설계 요약

## 원칙: Rule First

문자열과 구조로 판정되는 문제는 모델을 거치지 않고 규칙으로 잡습니다. 의미 판단이 필요한 항목만 로컬 모델에 묻고, 모델의 답은 원문과 대조될 때만 채택합니다.

이렇게 나누는 이유는 둘입니다. 규칙은 같은 입력에 같은 결과를 내서 치명급 항목을 믿고 막을 수 있습니다. 그리고 CPU 전용 환경에서 모델 호출 수가 곧 소요시간이라, 호출을 줄이는 것이 성능 최적화의 전부에 가깝습니다.

## 관점별 몫

| 관점 | 규칙 층 | 모델 층 | 사람·상위 리뷰 |
|---|---|---|---|
| 보안 | 비밀정보, 기본값, 주입 패턴, 약한 설정 | 인가 누락, 입력 검증 부재 | 인증 흐름 전체, 설정과 코드의 대조 |
| UX | 빈 catch, 누적 렌더, 디버그 출력 | 실패 안내, 진행 표시, 빈 상태 | 여정 전체 |
| 테스트 | 짝 없는 클래스, 단언 없음, only·skip | 약한 단언, 실패 경로 누락 | 회귀 범위 |
| 구조 | 명명·계층 규약 | 거의 불필요 | 공통화 판단 |
| E2E | 하니스에 없는 엔드포인트 | 시나리오 초안 | 실브라우저 실측 |

## 모델 층을 소형 모델에 맞추는 방법

1. **호출 단위를 좁힙니다.** 파일 1개 × 관점 1개 × 예·아니오 문항 4~5개입니다.
2. **입력을 줄입니다.** 바뀐 줄 앞뒤 30줄만 줄 번호를 붙여 보냅니다. 기본 상한은 6,000자입니다.
3. **출력을 강제합니다.** JSON 스키마(`response_format`)와 `temperature 0` 을 씁니다.
4. **근거를 대조합니다.** 모델이 낸 인용문이 지목한 줄 ±3줄 안에 공백 차이만 빼고 그대로 있어야 채택합니다.

## 보안 경계

- 모델 엔드포인트는 기본으로 `127.0.0.1`, `localhost`, `::1` 만 허용합니다.
- 규칙이 잡은 비밀값은 리포트·JSON·문제 패널 어디에도 원문으로 남지 않습니다.
- 엔진은 대상 저장소를 읽기만 합니다. 쓰는 것은 지정한 리포트 파일뿐입니다.

## 알려진 한계

파일 하나씩 보는 구조라서 여러 파일에 걸친 값의 흐름은 추적하지 않습니다. 앞으로 코드 심볼 색인으로 관련 파일을 문맥에 붙이는 방식을 검토합니다. 그래도 남는 몫은 사람이나 상위 리뷰에 맡기는 것을 전제로 합니다.

## 평가 계획

과거 리뷰에서 나온 치명·높음 지적을 정답으로 두고, 같은 변경에 이 도구를 돌려 아래를 잽니다.

| 지표 | 뜻 |
|---|---|
| 재현율 | 정답 중 이 도구가 잡은 비율 |
| 정밀도 | 이 도구의 지적 중 실제 문제 비율 |
| 소요시간 | 변경 1건당 전체 실행 시간 |
